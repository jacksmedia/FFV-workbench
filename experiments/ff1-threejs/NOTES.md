# FF1 three.js experiment — notes

A proof of concept that renders Final Fantasy 1 (NES, U) as a browsable
three.js world, with all data extracted from the ROM via everything8215's
ff6tools schema (`tools/ff1/ff1u-nes.json`). No hand-authored game data:
if it's on screen, it came out of the ROM.

## Files

| File | Role |
|---|---|
| `ff1_demo.html` | The whole demo — open directly in a browser (`file://` works) |
| `ff1_assets.js` | Generated by the extractor; `const FF1_ASSETS = {...}` (~1.3 MB) |
| `../../tools/ff1/extract_ff1_assets.py` | Extractor; run `python tools/ff1/extract_ff1_assets.py "Final Fantasy (U).nes"` from repo root |
| `ff1_world_preview.png` | Early world-map render |

Expected ROM CRC32: `AB12ECE6` (file or PRG). The extractor warns but
continues on mismatch.

## Phase history

- **Phase A — world + interiors + teleport graph** (done). 256×256 RLE world
  map, 61 interior 64×64 maps (RLE via pointer table at PRG $10000), 8
  interior tilesets, entrance/exit/teleport tables, hero sprite.
- **Phase B — text, dialog, NPCs, treasure** (done). 256 dialogs + 256 item
  names (DTE-compressed text), 290 NPC placements with sprites and dialog,
  treasure chests wired to item names.
- **Phase C — shops** (done 2026-07). 71-entry shop pointer table at
  0x0E8300 (bank 0E). Shop *type* is the table index: 1–10 weapon, 11–20
  armor, 21–30 white magic, 31–40 black magic, 41–50 clinic, 51–60 inn,
  61–70 item. Clinics/inns store one 16-bit price; the rest are
  zero-terminated item-id lists. Prices come from `itemProperties`
  (0x0DBC00, 2 bytes GP × 240 items). Interior tile special 1 with a nonzero
  arg is a shop door; the arg is the shop index. Demo: walk into a shop
  door → buy UI; inns/clinics heal for their ROM price.
- **Phase D — vehicles** (done 2026-07). `vehicleGraphics` at 0x029D00:
  3 entries × 0x180 bytes = six 2×2 frames each; order verified visually as
  **0=ship, 1=airship, 2=canoe**; palette `worldPalette[24:28]`.
  World tile byte0 is a *blocked-for-mode* bitfield: bit0 foot, bit1 canoe,
  bit2 ship, bit3 airship-can't-land, bit4 forest, bit5 ship-can-dock;
  bits6-7 special (1 chime, 2 caravan, 3 airship raising spot).
  Demo rules (all data-driven):
  - Ship parks on an ocean tile beside the nearest dock-flagged shore tile
    (dock tiles themselves are NOT ship-passable — the Coneria pier is 3
    tiles wide and only the center one touches ocean, hence the
    keep-searching placement). Step onto the ship to board; sail where bit2
    is clear; step onto a dock tile to go ashore (ship stays parked).
  - Airship spawns on the tile flagged special 3 — this lands it in the
    Ryukahn Desert region (≈216,234), its authentic raising point, purely
    from data. Stepping on it takes off; Enter lands (only where bit3 clear;
    the desert spot itself refuses landing, as in the real game). Flying is
    ~2.3× walk speed.
  - Canoe is carried from the start; stepping into a canoe-passable river
    auto-enters it, stepping ashore auto-exits. You can board the ship from
    the canoe.
  - Entrances and random battles trigger on foot only (real FF1 has
    river/ocean encounter domains — simplified here).

- **Phase E — real battles** (done 2026-07). Random encounters now use the
  ROM's own encounter tables end to end:
  - `battleGroup` (125 × 8 slots, weighted 12/12/12/12/6/6/3/1 per 64):
    groups 0–63 are 32×32-tile overworld domains (`(y>>5)*8 + (x>>5)`),
    64/65 river south/north, 66 ocean, and interior map *m* uses group
    *m*+64 (schema-confirmed). A slot's high bit selects the "B" variant
    counts. Encounter rate = `mapBattleProbability[0]` (world) or `[m+1]`
    (interior), rolled against 256 on battle-flagged tiles. Ship steps roll
    ocean battles, canoe steps roll river battles, the airship never does.
  - `battleProperties` (128 formations, 16 bytes): size type, gfx bank,
    up to 4 monster slots with min/max counts, 2-bit graphic assignment,
    and one of two formation palettes per slot.
  - **Monster graphics bank layout** (empirically verified — render + scan
    of all formations' assignment bits): each 0x800 bank holds backdrop
    fill at tiles 1–16, smalls (4×4 tiles) at 18–33 (asn 0) and 34–49
    (asn 2), larges (6×6) at 50–85 (asn 1) and 86–121 (asn 3). Exported as
    palette-index bitmaps; the demo colorizes at runtime with the
    formation's `monsterPalette` entries (that's how IMP/GrIMP share
    pixels), canvas → dataURL, cached.
  - Combat math is FF1's: to-hit = 168 + hit% − evade (of 200), damage =
    rand(atk, 2·atk) − absorb, crit adds an unabsorbed roll, multi-hit =
    1 + hit%/32, elemental/category weakness gives +4 atk / +40 hit%.
    Spell accuracy = 148 + acc − magic defense, resisted casts halve;
    weakness ×1.5, resistance ×0.5.
  - Fiend/Chaos formations (size 3/4, indices 115–123) are referenced by
    **no** encounter group, so random battles never need the special fiend
    tilemaps.
- **Phase F — party, equipment, magic** (done 2026-07). The hero is now a
  **Red Mage** (class 3 — chosen because Fighters can't cast, and a Red
  Mage exercises both the weapon shops and the magic shops). Real
  `classProperties` base stats, `classExperience` curve (L2 = 40 exp,
  shared by all classes), and `classStats` level-up records (byte0 flags:
  0x20 HP bonus / 0x10 str / 0x08 agi / 0x04 int / 0x02 vit / 0x01 luck,
  25% chance when unflagged; byte1 bits grant +1 spell charge for levels
  1–8). Item id spaces: 28–67 → `weaponProperties[id-28]`, 68–107 →
  `armorProperties[id-68]`, 176–239 → `spellProperties[id-176]`.
  Chests and shops route into a typed inventory; **I** opens the gear
  panel (equip 1 weapon + up to 4 armor pieces — absorb sums defense,
  weight subtracts from evade = 48 + agility; potions usable from the
  panel). Defeat is softened for the demo: wake outside Coneria with half
  your GP.

### Phase E/F simplifications (deliberate)
- Monster AI (`monsterAI` spell/skill lists) not wired — monsters attack
  physically only.
- Status spells (SLEP/LOCK/etc., effects 3/14/18) collapse to a
  "sleep n turns" approximation; poison/stone/death not modeled.
- Surprise/initiative, spell class-permission gating (`classSpells`), and
  per-terrain FF1 threat accumulator skipped.
- The battle backdrop uses the formation bank's own fill pattern tiles
  colored by the terrain's `battleBgPals` entry — an approximation of the
  real backdrop loader that looks right in practice.

## Candidate next phases

- **Phase G — monster AI & the fiend fights**: wire `monsterAI` spell/skill
  lists so mages cast back; scripted fiend battles need the special
  size-3/4 tilemaps (whole-bank images).
- **Class change & spell gating**: `classSpells` permissions, class-change
  upgrade (Red Wizard), `itemClass` equip restrictions (currently anyone
  can wear anything).
- **Polish**: walk animation frames, vehicle facing frames, battle
  animations, save state (localStorage), sound via the NSF driver.
- **Portability prize**: the extractor reads everything through the
  ff6tools schema (`rng()`/pointer tables/stringTables), so pointing this
  at `ff4-sfc.json` or `ff5-sfc.json` mainly means new decoders for SNES
  formats (4bpp CHR, ff5-lzss) — the demo's data contracts
  (tileProps/formations/groups/shops) are already engine-agnostic.

## Gotchas learned

- NES "mapped address" convention in the schema: `0xBBAAAA` = PRG bank BB
  (16 KB) : CPU addr AAAA → linear `bank*0x4000 + (addr & 0x3FFF)`.
- Planar ("interlace") tables: quadrant/field tables stored back to back;
  ff6tools interleaves on load, the extractor reads them directly.
- Interior door tiles are flagged foot-impassable in ROM; the game's door
  routine overrides that. The demo replicates the override (spec 1/2/4).
- Windows console chokes on Unicode in extractor output — run with
  `PYTHONIOENCODING=utf-8` (or the ✓ in the CRC message dies on cp1252).
